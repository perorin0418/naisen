# naisen

[koya](https://github.com/perorin0418/koya) の隔離コンテナの中と外（ホスト）で、ファイルとコマンドをやり取りするためのコマンド。
内線電話のように、ホストで `naisen` を起動すると自分の番号が出ます。koya の中から `naisen call 番号` でかけ、
ホストで受けると通話が始まり、**どちらの側からも**、相手側でのコマンドの実行とファイル・ディレクトリの送受信ができます。
電話はいくつでも起動できるので、複数の koya とそれぞれ通話できます。
名前の naisen は「内線」から。同じマシンの中（ホストとそのコンテナの間）でつなぐ前提だからです。

```console
host$ naisen
naisen: あなたの番号は 1 です（127.0.0.1:7651 で待っています。…）

(koya:mycc) $ naisen call 1
naisen: 番号 1（host.docker.internal:7651）にかけています… 確認コード 8196

host$                                   # ホストの画面に着信が出る
着信: me@koya-mycc（番号 1、linux、koya プロファイル mycc）
  作業ディレクトリ: /home/me/src/myapp
  確認コード: 8196（発信側の画面と同じか確かめてください）
受けますか？ [y/N]: y

(koya:mycc) naisen(1)> run git log -1 --oneline   # ホストで実行される
(koya:mycc) naisen(1)> send dist/app.zip           # ホストの作業ディレクトリに置く
(koya:mycc) naisen(1)> get ~/.config/foo.toml      # ホストのファイルを受け取る
(koya:mycc) naisen(1)> bye
```

## インストール

```bash
go install github.com/perorin0418/naisen/cmd/naisen@latest
```

ホストと koya の中の両方に入れます（同じ版を使ってください）。
koya のコンテナはカレントディレクトリをマウントしているので、ホストでビルドしたバイナリ（Linux 用）を
プロジェクトのディレクトリに置いて、koya の中から使うこともできます（`GOOS=linux go build -o bin/naisen ./cmd/naisen`）。

## 使い方

```
naisen [--number N] [--bind ADDR] [--once]   内線を起動して着信を待つ（起動すると自分の番号が出る）
naisen --auto [--number N] ...               自動で取る内線を起動する（koya の中で起動しておき、ホストからかける）
naisen call [番号][@ホスト]                   その番号に電話をかける（番号を省くと、待っている内線を探す）
naisen list [--local] [@ホスト]               ネットワークで待っている内線の一覧（電話帳）

通話中に、どちらの側でも別の端末から使えるコマンド（対話プロンプトでも同じ名前で使えます）:
naisen run [--line N] [-C DIR] [-n] [--] COMMAND...   相手側でコマンドを実行する
naisen send [--line N] [-f] LOCAL [REMOTE]            こちらのファイル・ディレクトリを相手側に送る
naisen get [--line N] [-f] REMOTE [LOCAL]             相手側のファイル・ディレクトリを受け取る
naisen gui [--line N] [--dir DIR] [--no-open]         ドラッグ&ドロップでファイルをやり取りするウィンドウを開く
naisen status [--line N]                              このマシンの電話の状態を表示する
naisen hangup [--line N]                              電話を切る

naisen version / naisen help [コマンド]
```

### 通話の始め方

1. ホストで `naisen` を起動します。「あなたの番号は 1 です」のように、自分の**番号**が出ます。
2. koya の中で `naisen call 1` を実行します。ホストを省略すると、`NAISEN_HOST`、なければ
   `host.containers.internal`（podman）、`host.docker.internal`（docker）、`127.0.0.1` の順に探します。
3. ホストの画面に、発信側のユーザー・ホスト名・作業ディレクトリ・**確認コード**（4桁）が出ます。
   発信側の画面のコードと同じか確かめて、`y` で受けます。15 分答えなければ断ります。
4. 両方の画面に `naisen(番号)>`（対話プロンプト）が出ます。`bye`（または Ctrl-D）で切ります。

- 1つの電話が同時に通話できる相手は1つです。通話中にかかってくると「話し中」で断ります。
- 電話が切れると、ホストの naisen はまた着信を待ちます（`--once` を付けると終わります）。
- ホストの naisen は、着信に答えるため端末から起動します。

### 番号と電話帳

- 番号は 1〜49 です。`naisen` は、このマシンで空いている最小の番号を使います。`--number N` で指定もできます。
  番号 N の電話は TCP の `7650+N`（番号 1 なら 7651）で待ち受けます。
- 電話はいくつでも起動できます。ホストで端末を2つ開いて `naisen` を2回起動すれば、番号 1 と 2 になり、
  2つの koya がそれぞれ `naisen call 1`・`naisen call 2` でかけられます。
- `naisen call` で番号を省くと、ホストで待っている電話を探し、空いている電話が1つならそこにかけます。
  複数あれば一覧を出すので、番号を指定してかけ直します。
- `naisen list` で、ネットワークで待っている内線の一覧（電話帳）を見られます。着信にはなりません。次の2つを合わせて表示します。
  - ホストの候補（コンテナの中ならホストとそのコンテナ自身、ホストなら `127.0.0.1`）の番号 1〜49 に TCP で問い合わせて見つけた内線。
    このマシンの内線と、ポートを公開したコンテナの内線が出ます。
  - LAN にブロードキャスト（UDP）で問い合わせて、返事のあった内線。`--bind 0.0.0.0` などで待っている、ほかのマシンの内線が出ます。
    内線は TCP と同じアドレス・ポートの UDP で問い合わせに答えるので、`127.0.0.1` だけで待つ内線はほかのマシンからは見えません。
    `--local` を付けるとブロードキャストをしません。

```console
host$ naisen list
  かけ方            状態        取り方          相手               作業ディレクトリ
  1@127.0.0.1       話し中      手で取る        me@myhost          D:\src\app1
  11@127.0.0.1      待ち受け中  自動            me@koya-mycc       /home/me/src/app1
  1@192.168.1.20    待ち受け中  手で取る        you@otherpc        /home/you/work
```

- かける側（`naisen call`）の電話にも、そのマシンで空いている番号が付きます。相手の画面の着信にも出ます。

### 自動で取る内線（koya の中で起動して、ホストからかける）

`naisen --auto` は、着信をたずねずに自動で受ける内線です。端末がなくても（バックグラウンドでも）起動できます。
koya の中で起動しておけば、ホストからいつでもかけられます。

```console
# koya のコンテナを、内線のポートを公開して作る（番号 11 → ポート 7661）
host$ koya run mycc -p 127.0.0.1:7661:7661

# koya の中で、自動で取る内線を起動しておく
(koya:mycc) $ naisen --auto --number 11 &
naisen: あなたの番号は 11 です（0.0.0.0:7661 で待っています。…）
naisen: 自動で取ります（このポートに届く誰からの着信も、確かめずに受けます）

# ホストからかける（すぐにつながる）
host$ naisen call 11
```

- **ポートの公開が要ります。** コンテナの中の待ち受けにホストから届くようにするため、コンテナを作るときに
  ポート `7650+番号` を公開します（koya の `-p` はコンテナを作るときだけ効くので、作り直しが要ります）。
  公開するホスト側のポートはホストの内線と同じ番号の空間を使うので、ホストの内線とぶつからないよう、
  koya の中の番号は `--number 11` などで決めておくと扱いやすくなります。
- コンテナの中では、`--bind` の既定が `0.0.0.0` になります（コンテナの中の `127.0.0.1` には、ポートを公開してもホストから届かないため）。
- **確かめずに受けます。** そのポートに届く誰でも（同じネットワークのほかのコンテナなども）つながり、このコンテナでコマンドを実行できます。
  ポートの公開は `-p 127.0.0.1:...` のようにホストの中だけにして、届く範囲を限ってください。
- 通話のあいだも、自動で取った側（koya の中）からホストに `naisen run` などをできるのは、ふつうの通話と同じです。
- 電話が切れると、また着信を待ちます。

### 対話プロンプト

| コマンド | 意味 |
|---|---|
| `run COMMAND` | 相手側でコマンドを実行する（行の残りをそのまま相手のシェルに渡す） |
| `send [-f] LOCAL [REMOTE]` | こちらのファイル・ディレクトリを相手側に送る |
| `get [-f] REMOTE [LOCAL]` | 相手側のファイル・ディレクトリを受け取る |
| `status` | 通話の状態を表示する |
| `gui` | ドラッグ&ドロップのウィンドウを開く（`naisen gui` と同じ） |
| `help` | 使い方を表示する |
| `bye` | 電話を切る（`exit`・`quit`・Ctrl-D でも切れます） |

実行中の `run`・`send`・`get` は Ctrl-C で止めます。空白を含むパスは `'` か `"` で囲みます。
相手から依頼があると、受けた側の画面に `← 相手が実行: ...` のように表示します。

### 単発コマンド（別の端末から）

通話中は、同じ側の別の端末（同じユーザー）から `naisen run`・`send`・`get` を1回ずつ使えます。
koya の中の Claude Code などから、ホストのコマンドやファイルを使わせるときに便利です。

このマシンで通話中の電話が1つなら、それを使います。複数の電話が通話中のとき（ホストで2つの koya と話しているときなど）は、
`--line 番号`（自分の電話の番号）か環境変数 `NAISEN_LINE` で選びます。`naisen status` で、このマシンの電話の一覧と状態が出ます。

```bash
naisen run make test                 # ホストで実行。終了コードもホストのもの
naisen run 'ls | wc -l'              # パイプなどを相手側で解釈させるときは引用符で囲む
git diff | naisen run patch -p1      # 標準入力が端末でないときは、相手側のコマンドに渡す
naisen send build/out.tar.gz /tmp/   # 相手側の /tmp/ に置く
naisen get -f logs ./logs            # 相手側の logs ディレクトリを受け取る（上書き可）
naisen run --line 2 hostname         # 番号 2 の電話の相手で実行する
```

標準入力を端末で使わないとき（バックグラウンドなど）は、`naisen call` は対話プロンプトを出さずに通話だけを続けます。
`naisen hangup` か Ctrl-C で切ります。

```bash
naisen call < /dev/null &            # koya の中で発信だけしておく（ホストで受ける）
naisen run hostname                  # 以後は単発コマンドで使う
naisen hangup
```

### ドラッグ&ドロップのウィンドウ（`naisen gui`）

通話中の対話プロンプトで `gui` と打つと、ファイルをドラッグ&ドロップでやり取りするウィンドウが開きます
（別の端末から `naisen gui` でも開けます）。主にホスト（Windows など、画面のある側）で使います。
ウィンドウは1つの電話につながります。対話プロンプトの `gui` はその電話、`naisen gui` は `--line 番号` の電話です
（このマシンの電話が1つか、通話中の電話が1つなら省略できます）。

- ウィンドウには**相手側**のディレクトリの一覧が出ます。フォルダーはダブルクリックで開き、↑ で上に戻ります。
  パスの欄に入力して Enter でも移動できます。
- **送る**: エクスプローラーなどからファイル・フォルダーをウィンドウにドロップすると、表示中の相手側のディレクトリに送ります。
- **受け取る**: 一覧の項目をウィンドウの外（エクスプローラーやデスクトップ）へドラッグすると、そこに受け取ります
  （Edge・Chrome のときだけ。フォルダーは zip になります）。「受け取る」ボタンでは、`--dir` のディレクトリ
  （既定は `naisen gui` を実行したディレクトリ）に受け取ります。
- 「上書き」にチェックを入れると、置き先にすでにあっても上書きします（`-f` と同じ）。

ウィンドウは Edge か Chrome のアプリモード（アドレスバーのないウィンドウ）で開きます。見つからなければ既定のブラウザーで開きます。
中身は `naisen gui` が `127.0.0.1` の空いているポートで動かす小さな Web サーバーで、URL に含まれるトークン（推測できない文字列）がないと使えません。
画面を表示できない環境（koya の中など）では、表示された URL を同じマシンのブラウザーで開いてください。
ウィンドウを閉じると `naisen gui` も終わります。通話を始める前に開いておくと、通話が始まったところで一覧が出ます。

- 空のフォルダーは送れません（中のファイルだけを送るため）。
- ドロップしたファイルはいったん一時ディレクトリに置いてから相手側に送ります。

### パスと作業ディレクトリ

- 相手側のパス（`send` の REMOTE、`get` の REMOTE）とコマンドの作業ディレクトリは、
  **相手の naisen を起動したディレクトリ**が基準です（`~` は相手のホーム）。`naisen run -C DIR` で変えられます。
- 置き先が既存のディレクトリなら、その中に元の名前で置きます。そうでなければ、その名前で置きます（`cp` と同じ）。
- 置き先にすでにあると止まります。`-f` を付けると上書きします（ディレクトリは中身を重ねます）。
- ディレクトリはまとめて送れます（中身・パーミッション・シンボリックリンクも含む）。展開は置き先の外に出ないようにしています。

### コマンドの実行

- 相手側の `sh -c`（Windows は `cmd /C`）で実行します。`NAISEN_SHELL` で変えられます（例: `NAISEN_SHELL="pwsh -NoProfile -Command"`）。
- 標準出力・標準エラー出力は分けて返し、終了コードもそのまま返します。
- Windows 側で実行したコマンドの出力は UTF-8 にそろえて返します。出力が UTF-8 として正しくなければ、
  コンソールのコードページ（日本語の環境なら CP932）とみなして変換します（git など UTF-8 で出すものはそのまま）。
  相手側のコマンドに渡す標準入力は変換しません。
- 端末を必要とするコマンド（vim、対話シェルなど）は使えません。
- Ctrl-C で相手側のコマンドを止めます（Linux・macOS ではプロセスグループごと止めます）。

## セキュリティ

- **受けると、相手はこちらの権限で何でも実行でき、ファイルを読み書きできます。** これはホストからコンテナへの向きも、
  コンテナからホストへの向きも同じです。koya の隔離をこの通話の間だけ外すことになるので、
  信用しないコードが動いているコンテナからの着信は受けないでください。
- ホストの naisen は既定で `127.0.0.1` だけで待ち受けます。podman machine や Docker Desktop など、VM の中でコンテナを動かす環境では、
  コンテナからの `host.containers.internal`（`host.docker.internal`）は多くの場合ホストの `127.0.0.1` に届きます。
  Linux で docker を直接使う場合など、届かない環境では `--bind 0.0.0.0` を使い、
  コンテナを `--add-host=host.docker.internal:host-gateway` 付きで作るなどしてください。その場合はほかのマシンからも着信できます。
- 通信は暗号化していません。同じマシンの中で使う前提です。
- 確認コードは、着信が自分の発信によるものかを確かめるためのものです。
- 電話帳（`naisen list`）の問い合わせ（TCP と UDP）には、着信を受けなくても、番号・状態・取り方・ユーザー名・ホスト名・
  作業ディレクトリを答えます。`--bind 0.0.0.0` で待つ内線は、LAN のどこからでも見えます。
- 自動で取る内線（`--auto`）は、そのポートに届く誰からの着信も確認なしでつなぎます。届く範囲が限られているときだけ使ってください。
- 単発コマンドは、電話ごとの制御ソケット（UNIX ドメインソケット。`$XDG_RUNTIME_DIR` か一時ディレクトリの
  `naisen-<ユーザー名>/<番号>.sock`、所有者だけが使える）を通ります。

## 環境変数

| 名前 | 意味 |
|---|---|
| `NAISEN_HOST` | `naisen call`・`naisen list` でかける先のホスト |
| `NAISEN_BIND` | `naisen` の待ち受けアドレス（既定 `127.0.0.1`） |
| `NAISEN_LINE` | 単発コマンドと `naisen gui` で使う電話の番号（`--line` と同じ） |
| `NAISEN_SHELL` | 相手から頼まれたコマンドを実行するシェル（既定 `sh -c`、Windows は `cmd /C`） |
| `NAISEN_SOCK_DIR` | 制御ソケットを置くディレクトリ |

## 仕組み

- ホストと koya の間は TCP の1本の接続です。メッセージ（フレーム）は「ヘッダーの長さ・データの長さ（各4バイト）+
  JSON のヘッダー + データ」で、依頼ごとに番号を付けて、複数の依頼を同時に流せます（発信側は奇数、受信側は偶数）。
- ファイルは tar 形式にまとめて、32 KiB ずつ送ります。
- 単発コマンドは、制御ソケットで通話中のプロセスにつなぎ、プロセスが相手との間を中継します。対話プロンプトも同じ経路を使います。
