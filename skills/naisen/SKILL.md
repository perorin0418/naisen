# naisen の使い方

naisen は、[koya](https://github.com/perorin0418/koya) の隔離コンテナの中と外（ホスト）を、内線電話のようにつなぐコマンド。
通話中は、**どちらの側からも**、相手側でのコマンドの実行とファイル・ディレクトリの送受信ができる。

Claude Code から使うのは、通話中に別の端末から1回ずつ使える**単発コマンド**（`naisen run`・`send`・`get`・`status`・`hangup`）。
対話プロンプト（`naisen(番号)>`）や着信の `y/N` は端末で人が操作するもので、Claude Code からは使わない。

## 最初に確かめること

1. `naisen version` で入っているか確かめる。無ければ、利用者に入れてもらう（下の「入っていないとき」）。
2. `naisen status` で、このマシンの電話（naisen のプロセス）と状態を見る。
   - 「このマシンで動いている naisen はありません」→ まだ通話していない。下の「通話の始め方」へ。
   - 通話中の電話が1つ → そのまま単発コマンドを使える。
   - 通話中の電話が複数 → `--line 番号`（自分の側の電話の番号）を付けて選ぶ。どれを使うか分からなければ利用者に聞く。

## 単発コマンド

```bash
naisen run -n -- make test                # 相手側で実行する。終了コードは相手側のもの
naisen run -n 'ls | wc -l'                # パイプなどを相手側で解釈させるときは、まとめて引用符で囲む
git diff | naisen run patch -p1           # 標準入力が端末でないときは、その内容を相手側のコマンドに渡す
naisen run -n -C /path/to/dir -- git status   # 相手側の作業ディレクトリを変える
naisen send build/out.tar.gz /tmp/        # こちらのファイル・ディレクトリを相手側に置く
naisen get logs ./logs                    # 相手側のファイル・ディレクトリを受け取る
naisen get -f logs ./logs                 # 置き先にすでにあっても上書きする（ディレクトリは中身を重ねる）
naisen run --line 2 -n hostname           # 番号 2 の電話の相手で実行する
```

- **標準入力を渡さないときは `-n` を付ける。** 標準入力が端末でないと、naisen はその内容を相手側のコマンドに渡す。
  Claude Code の Bash では標準入力が端末でないことがあるので、渡すものが無いときは `-n` を付けて、入力待ちで止まらないようにする。
- 相手側では `sh -c`（Windows は `cmd /C`。`NAISEN_SHELL` で変えられる）で実行する。ホストが Windows なら、`cmd` の書き方になる。
  相手側の OS が分からなければ `naisen run -n -- ver` を試す（Windows なら版が出る。そうでなければ `uname -a`）。
- 標準出力と標準エラー出力は分けて返り、終了コードもそのまま返る。
- 端末を必要とするコマンド（vim、対話シェル、ページャーなど）は使えない。git なら `--no-pager` を付ける。
- 相手側の相対パスとコマンドの作業ディレクトリは、**相手が naisen を起動したディレクトリ**が基準（`~` は相手のホーム）。
- 置き先が既存のディレクトリならその中に元の名前で置き、そうでなければその名前で置く（`cp` と同じ）。
  置き先にすでにあると止まる。上書きしてよいか分からなければ、`-f` を付ける前に利用者に聞く。
- 空白を含むパスは引用符で囲む。

## 通話の始め方

通話を始めるには、受ける側で人が確認コードを見て `y` を押す必要がある（自動で取る内線を除く）。Claude Code だけでは始められないので、利用者に頼む。

### koya の中から、ホストにかける（ふつうの使い方）

1. 利用者に、ホストの端末で `naisen` を起動してもらう。「あなたの番号は 1 です」のように番号が出る。
2. koya の中で、バックグラウンドで発信する。標準入力が端末でないと、対話プロンプトを出さずに通話だけを続ける。

   ```bash
   naisen call < /dev/null > /tmp/naisen-call.log 2>&1 &   # 待っている内線が1つならそこにかける
   naisen call 1 < /dev/null > /tmp/naisen-call.log 2>&1 & # 番号を指定してかける
   ```

   Bash ツールの `run_in_background` で動かしてもよい。
3. 出力に出る**確認コード**（4桁）を利用者に伝え、ホストの画面の確認コードと同じか確かめて `y` で受けてもらう。
4. `naisen status` で通話中になったことを確かめてから、単発コマンドを使う。
5. 終わったら `naisen hangup` で切る（自分で始めた通話だけ。利用者が始めた通話は勝手に切らない）。

- ホストが見つからないときは、`NAISEN_HOST`、なければ `host.containers.internal`（podman）、`host.docker.internal`（docker）、
  `127.0.0.1` の順に探す。`naisen list --local` で、待っている内線の一覧（電話帳）を見られる。
- 待っている内線が複数あると、一覧を出して止まる。どれにかけるかは利用者に聞く。

### ホストから、koya の中にかける

koya の中で自動で取る内線（`naisen --auto --number 11`）が動いていれば、ホストから `naisen call 11` ですぐにつながる。
これにはコンテナを作るときのポートの公開（`koya run ... -p 127.0.0.1:7661:7661`）が要る。
自動で取る内線は、そのポートに届く誰からの着信も確かめずに受けるので、**利用者の指示なしに起動しない**。

## 守ること

- **通話中は、相手側を相手のユーザーの権限で操作できる。** koya の中から使うときは、koya の隔離の外（ホスト）を操作することになる。
  ホストでのファイルの削除・上書き、設定の変更、パッケージの導入、外部への送信など、取り消しにくい操作は、実行する前に利用者に確認する。
- `--bind 0.0.0.0` や `--auto` での起動は、ほかのマシンやコンテナからも着信できるようになる。利用者の指示があるときだけ使う。
- 通信は暗号化していない。認証情報などの秘密を、必要もなく送らない。
- `naisen gui` はブラウザーでウィンドウを開く人向けの機能。Claude Code からは使わない（利用者に頼まれたときを除く）。

## 入っていないとき

[Releases](https://github.com/perorin0418/naisen/releases) から OS と CPU に合ったファイルを取り、中の `naisen` を PATH の通った場所に置く。
Go があれば `go install github.com/perorin0418/naisen/cmd/naisen@latest` でも入る。
ホストと koya の中の両方に、同じ版を入れる。入れるかどうか・どこに入れるかは利用者に確かめる。

入っている naisen を最新版にするときは `naisen self-update`（新しい版があるかだけ見るなら `--check`）。
実行中のバイナリを置き換えるので、実行する前に利用者に確かめる。ホスト側を更新するとき（`naisen run naisen self-update`）も同じ。
起動中の電話は古い版のまま動くので、切って起動し直すまで新しい版にならない。

## 困ったとき

- 「通話中ではありません」→ 通話していない。`naisen status` で状態を見て、上の「通話の始め方」へ。
- 「通話中の電話が複数あります」→ `--line 番号` を付ける。
- 「話し中」→ その電話はほかの相手と通話している。1つの電話が同時に通話できる相手は1つ。
- 詳しい使い方は `naisen help`、コマンドごとは `naisen help run` のように見る。
